\begin{slide}

	\slidetitle{Operating Systems Make Different Design Choices}

	Windows, Linux, macOS, Android, iOS, and ChromeOS all manage similar hardware.

	\bigskip

	They differ in choices such as:

	\begin{itemize}
		\item Which abstractions and interfaces they expose
		\item Which policies decide how resources are shared
		\item How much operating-system code runs with full privilege
	\end{itemize}

	\bigskip

	The placement of privileged services is a kernel architecture decision.

\end{slide}

\begin{slide}
  
  \slidetitle{Kernel Structure Is a Design Trade-off}

  \begin{columns}[T,onlytextwidth]
    \begin{column}{0.46\textwidth}
      \textbf{More in kernel space}
      \begin{itemize}
        \item Direct communication
        \item Lower boundary-crossing cost
        \item Larger trusted code base
      \end{itemize}
    \end{column}
    \begin{column}{0.50\textwidth}
      \textbf{More in user space}
      \begin{itemize}
        \item Better service isolation
        \item More message passing
        \item Smaller privileged core
      \end{itemize}
    \end{column}
  \end{columns}

  \bigskip

  Real systems often use hybrid choices. The useful question is \textbf{which services need privilege, and what cost does that choice create}.
\end{slide}

\begin{slide}

	\slidetitle{Summary}

	\begin{itemize}
		\item The kernel manages shared processors, memory, devices, and system state
		\item CPU modes let trusted kernel code enforce isolation from applications
		\item System calls let applications request OS services in a controlled way
		\item Kernel architectures choose which services run with privilege
	\end{itemize}

	\bigskip
